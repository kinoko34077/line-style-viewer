## 実装境界

トーク画面のヘッダー、送受信の履歴、フッターを縦方向の3領域に分ける。実スクリーンショットで共通する「戻る、名前、検索、通話、日付/カレンダー、メニュー」「＋、カメラ、画像、Aa入力欄、絵文字、マイク」を画面構成として配置。LINEと接続するアプリではないため、検索・通話・投稿・ファイル送信などの動作は模倣しない。**操作可能なのは右上の設定、手元のTXT読込、送信者選択、会話形式、表示倍率、テーマだけ**。端末OSの時計、通信・電池残量、独立したキーボード/提案候補帯は再現しない（重複するため）。

トーク名はエクスポート行 `[LINE] Bとのトーク履歴` または `[LINE] グループ名のトーク履歴` から元の名前部分だけ抽出し、`textContent`で安全に表示。名前がない入力は `トーク履歴`。原TXT/日付/送信者推定を改変せず、既存パーサーの重複排除も維持。

`--ui-scale` のCSS `zoom`（0.8〜1.6、初期1.2）を`.app-shell`全体へ適用するため、**ヘッダー・トーク本文・アイコン・日付/時刻・フッターが同時に拡大縮小**する。画面の縦割りは `100dvh / --ui-scale`で補正し、ヘッダーとフッターを残して会話だけスクロールさせる。設定パネルは画面拡大に追随させず、操作しやすい固有のタップ寸法を維持。長文は折り返し、狭い画面は一部装飾アイコンを省略。

3つの独立したローカル表示パレットを用意する。**通常**は既存の雲画像 `default/bg-sky.jpg`、明るい緑・白吹き出し、白入力欄。**ブラック**は暗色の背景・灰色/深緑吹き出し・高明度文字。**ホワイト**は明るい無地背景・白/淡緑吹き出し・濃色文字。LINEで販売されている個別の有料着せかえデザインをコピーせず、名称に合った配色をローカルで定義する。

## 受入条件

リポジトリにあるHTML/CSS/JSをChromiumで実際に読み込み、合成した非個人データ3,000件を`#fileInput`へ投入する。320/375/390/430/768pxで会話領域の内部スクロール、固定上下バー、ヘッダーの抽出タイトル、各テーマの色と雲背景有無、80/120/160%ズームに対する実寸変化、個チャ/グループ切り替え、横はみ出しなしを検査する。ソースと実メッセージの改変は許容しない。検証のPNG/JSONは期間限定Actions Artifact。公開Pages/iOS Safariの実機確認は Issue #10 が別途保有する。
