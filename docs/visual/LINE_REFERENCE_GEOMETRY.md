# LINE トーク表示 — 解像度非依存の参照基準（2026-10-13）

## 目的・判定方法

画面の解像度、DPI、キャプチャ倍率、フォントレンダリングが異なるため、**個別スクリーンショットのピクセル数の一致ではなく、形状・情報階層・横幅に対する相対位置**を複数資料で比較する。

基準単位は実際に表示されるトーク領域の幅 `W` と吹き出し・アイコン・時刻のバウンディングボックス。計測項目：`incomingBubbleLeft / W`、`(W - outgoingBubbleRight) / W`、`avatarDiameter / W`、`bubbleWidth / W`、`fontSize / W`、隣接メッセージの垂直間隔／行高、吹き出しの尻尾と角丸、既読・時刻の上下・左右順序。UIヘッダー部分はビューア機能であり、トーク領域と別に評価する。

## 観測に基づく共通構造

1. 受信は白で左＋アイコン。送信は緑で右、自己アイコンなし。時刻は吹き出し下端、送信のみ既読が時刻の上。
2. 吹き出しの始端は短い曲線尻尾を持つが、同じ送信者の**同じ分**の通常メッセージが続く表示例では、後続を楕円状の尻尾なしにする。受信側はアイコンのための横位置を維持する。
3. 長文は画面幅に対する最大割合を制限し、時刻と既読のために隣接した独立した領域を確保する。ブラウザの内容が収まらず横スクロールを生むことは許容しない。
4. 画面外周の余白・アイコン寸法・吹き出し角丸などの**CSS論理ピクセル値**はDPIに依存しない。日本語書体はOSの標準ゴシック（iOSのヒラギノなど）を優先する。
5. 日付・通知を中央カプセルへ置く。テキスト書き出しに記録がない実際の既読状態やスタンプ画像は復元しない。

## ローカルChromium測定（代表レイアウト再現）

2026-10-13実施。画面幅 `320 / 375 / 390 / 430 / 600 / 768` 論理px。ローカル静的サンプルは本番CSSの主要幾何と提供された匿名履歴の初期発言を再現（本番GitHub Pagesそのもののスクショではない）。

- `document.documentElement.scrollWidth === window.innerWidth` : 全6幅で成立。
- 390pxで受信吹き出しの左端は画面幅の **12.3%**、送信吹き出しの右余白は **2.1%**（このサンプル内の最初の各発言）。
- 320pxで受信左端 **15.0%**、送信右余白 **2.5%**。
- 連投3件の受信アイコン省略、尻尾非表示、後続時刻維持をサンプルで確認。
- 600pxを超える表示幅では `#chatContainer max-width:600px` のため、表示余白が増加。タブレット等への自然な中央寄せであり、スマホ幅比率をそのまま維持しない。

**限定**：ネット掲載スクショの元画素ファイルを同環境へ取得できていないため、数値はあくまでローカル側のブラウザ実測である。異なる会話の2画面を画素差分で割り算しても「本家一致率」にはならない。本家LINEの参照画像については形状・並び・色・構造を目視比較した。ピクセル一致率、現行LINE内部実装の具体値、時代を通じた不変仕様としての断定は禁止する。

### 実際の表示で確認された問題と解決方式

旧 `style.css` では、最初の白吹き出しが左上半径 **6px**、別図形の尻尾が **16×16px**・`top:2px`・`left:-8px` だった。局所拡大したブラウザ画像では、角丸の途中と尻尾の接合に青背景の小さな切れ込み／不自然な直線が生じている。ネット上の丸い肩と接合が違っていた。

新方式：最初の受信と送信の丸肩を **18px** とし、`20×22px` の2次元ベジェ輪郭を `top:0` に重ね、尻尾の**12px分を吹き出し内部まで重ねて**上肩へ自然につながるようにする。送信側は正確な左右反転形。外への張り出しは8pxを超えない。連投後続の尻尾非表示は維持。CSS論理pxは表示端末のDPIに応じてラスタライズされるので、異なる解像度でも**形状の関係**が維持される。

### 修正後ローカル描画の検証

Chromiumローカルの会話抜粋＋本番と同じ吹き出し主要CSS形状を再描画し、`320, 375, 390, 430, 600, 768` CSS幅で `document.documentElement.scrollWidth == innerWidth` を確認。相手側先頭吹き出し位置はスマホの画面左から48px、自己側の右余白8pxで維持。すべての幅で受信先頭 `::after` は `20px×22px;top:0`、連投後続は `display:none`。対照画像は `/mnt/data/line_bubble_before_after_390.png` （ローカル作業用であり、公開サイトに保存されていない）。元の履歴全文は公開リポジトリへ置いていない。

**検証境界**：これらはローカル描画の幾何計測値。参照ウェブ画像自体の画素データを容器へ取得できなかったため、本家との画素重ね合わせによる一致率は未算出である。改善は「本家と共通する角丸・尻尾の形状構造」と「各幅でのCSSの一貫性」に対するもので、公式LINE UIの内部寸法が18px／20pxだと断定していない。

## 実画像との画素比較（2026-10-13）

公開LINEスクリーンショットの原画像をGitHub Actionsで取得できた。参照画像： https://smartphone-hunter.com/wp-content/uploads/2021/08/smartphone-hunter.com_-79.png （1280×1280）。ブラウザ側は実際のリポジトリのHTML/CSS/JSをChromiumで読み込み、同一の文章「自分のメッセージ」「相手のメッセージ」をレンダリングした。参照画像は一時利用のみとし、マスク・重ね合わせ結果・寸法指標をActions artifactとして出力。

| 比較対象 | 参照画像の吹き出し矩形 | ビューア変更前 | 正規化輪郭IoU |
| --- | --- | --- | --- |
| 相手・白 | 425×101元画像px ≒170×40.4 CSS px | 146×38 CSS px | 0.97747 |
| 自分・緑 | 424×101元画像px ≒169.6×40.4 CSS px | 145×37 CSS px | 0.97950 |

参照画像のトーク領域1100pxとビューアの440 CSS pxを対応付け、換算倍率は約2.5。輪郭IoUは各マスクを縦横別々に256pxへ変換して計算した**形状だけの重なり率**。全画面一致率を意味せず、縦横比・寸法は別指標で評価する。

実参照マスクとのローカル描画候補比較によって、スマホ用の本文17px、行高1.3、上下余白9px、左右15pxが寸法差を縮小。ローカル候補の矩形は受信170×40px、送信169×40px、輪郭IoUはそれぞれ約0.9851、約0.9874。Actions側で再検証が必要。

参照画像の緑色代表値RGB(110,230,122)、別サイトのスクショ https://shop.menz-style.com/cdn/shop/files/fc-3276_5.jpg?width=600 ではRGB(155,224,97)と差がある。後者の文章内容は一致しないため、サイズ比較・輪郭一致率の統合スコアには混入させない。複数年代・端末によって緑色が変わり得るため、一例への色合わせはしない。
