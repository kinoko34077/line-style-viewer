# LINE トーク表示 — 解像度非依存の参照基準（2026-10-13）

## 目的・判定方法

画面の解像度、DPI、キャプチャ倍率、フォントレンダリングが異なるため、**個別スクリーンショットのピクセル数の一致ではなく、形状・情報階層・横幅に対する相対位置**を複数資料で比較する。

基準単位は実際に表示されるトーク領域の幅 `W` と吹き出し・アイコン・時刻のバウンディングボックス。計測項目：`incomingBubbleLeft / W`、`(W - outgoingBubbleRight) / W`、`avatarDiameter / W`、`bubbleWidth / W`、`fontSize / W`、隣接メッセージの垂直間隔／行高、吹き出しの尻尾と角丸、既読・時刻の上下・左右順序。UIヘッダー部分はビューア機能であり、トーク領域と別に評価する。

## 観測に基づく共通構造

1. 受信は白で左＋アイコン。送信は緑で右、自己アイコンなし。時刻は吹き出し下端、送信のみ既読が時刻の上。
2. 吹き出しの始端は短い曲線尻尾を持つが、同じ送信者の**同じ分**の通常メッセージが続く表示例では、後続を楕円状の尻尾なしにする。受信側はアイコンのための横位置を維持する。
3. 長文は画面幅に対する最大割合を制限し、時刻と既読のために隣接した独立した領域を確保する。ブラウザの内容が収まらず横スクロールを生むことは許容しない。
4. 画面外周の余白・アイコン寸法・吹き出し角丸などの**CSS論理ピクセル値**はDPIに依存しない。日本語書体はOSの標準ゴシック（iOSのヒラギノなど）を優先する。
5. 日付・通知を中央カプセルへ置く。テキスト書き出しに記録がない実際の既読状態やスタンプ画像は復元しない。

## ローカルChromium測定（代表レイアウト再現）

2026-10-13実施。画面幅 `320 / 375 / 390 / 430 / 600 / 768` 論理px。ローカル静的サンプルは本番CSSの主要幾何と提供された匿名履歴の初期発言を再現（本番GitHub Pagesそのもののスクショではない）。

- `document.documentElement.scrollWidth === window.innerWidth` : 全6幅で成立。
- 390pxで受信吹き出しの左端は画面幅の **12.3%**、送信吹き出しの右余白は **2.1%**（このサンプル内の最初の各発言）。
- 320pxで受信左端 **15.0%**、送信右余白 **2.5%**。
- 連投3件の受信アイコン省略、尻尾非表示、後続時刻維持をサンプルで確認。
- 600pxを超える表示幅では `#chatContainer max-width:600px` のため、表示余白が増加。タブレット等への自然な中央寄せであり、スマホ幅比率をそのまま維持しない。

**限定**：ネット掲載スクショの元画素ファイルを同環境へ取得できていないため、数値はあくまでローカル側のブラウザ実測である。異なる会話の2画面を画素差分で割り算しても「本家一致率」にはならない。本家LINEの参照画像については形状・並び・色・構造を目視比較した。ピクセル一致率、現行LINE内部実装の具体値、時代を通じた不変仕様としての断定は禁止する。
