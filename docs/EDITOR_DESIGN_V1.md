# LINE風トーク作成 — 編集モデルとローカル保存 v1

2026-10-14。元の閲覧器のLINE TXT/MD取込・分割バックアップの重複排除、雲背景、送受信／日付／時刻表示を引き継ぎ、**編集可能なトーク作成サイト**を主機能にする。元のTXTファイルは書き換えない。

## 画面・操作

- トーク一覧が空でもトークを新規作成できる。下部テキスト欄へ入力し、送信またはIME変換中でないEnterで**ローカル文書へ追加**する。Shift+Enterは改行。LINEサーバへ送信しない。
- 「＋」から相手の文章／システム通知／日付／未指定写真／未指定ファイルを挿入。写真とファイルのアイコンは直接素材追加へつながる。
- 既存の文章・時刻・システムメッセージ・日付は**ダブルタップでインライン編集**に切替。通常時はLINE本来の文字・吹き出しと同様に表示し、タップ選択した1項目の吹き出し右上にだけ削除×を表示する。初回の空画面にはTXT/MD読込ボタンも用意する。
- ドラッグ専用の⠿ハンドルは設けず、**吹き出し本体を直接ドラッグ**する。マウスは移動開始時（6px超）、タッチは320msの長押し後に開始して、通常の縦スクロールやダブルタップと競合させない。落としたX位置で左（相手）／中央（システム）／右（自分）、Y位置で並び順を決定。中央→左右へ戻す際、元のメッセージ形式を可能なら回復。
- ヘッダー右上はUndo／Redo／保存形式選択（TXT/JSON）／ハンバーガー。Undo/RedoはボタンとCtrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+Y。標準は40ステップ以内か履歴文字列合計32MB以内（大きなメディアを含む場合は履歴数を早めに制限）。
- ハンバーガー内のLINE風設定画面は、添付されたiPhoneの本家メニューを**情報配置の参考**とする。相手プロフィール行で参加者名・アイコン・投稿者を編集。写真・動画行で未指定素材を一覧し、各項目をタップしてブラウザ内の画像・動画・ファイルを指定。未指定のトーク行からも直接ファイル選択できる。BGM／アルバム／ノート／カレンダー／イベント／リンクは本家らしい表示項目だが、LINE連携やそれらの独立機能は実装していない。偽の動作を付けない。
- 作成・表示設定には既存LINE TXT/MD取込、自分と会話形式、80–160%画面拡大、通常・ブラック・ホワイト、JSONプロジェクト取込、新規作成／TXT・JSON書出しを統合する。

## 編集データ

\`editor.js\`が持つ独立した版付き文書 \`{version:1,title,self,mode,scale,theme,participants,items}\`。
各項目 \`{id,type,side,speaker,time,content,media,previousType,previousSpeaker,callKind}\` のうち \`type\` は text / attachment / date / system / call、\`side\` は me / you / system。参加者は名前とローカル画像データを持つ。\`media\` は \`{data,mime,name}\`。IDで対応付け、表示順は items の順序を正本とする。 話者名とsideは一体の意味状態として整合させる（送信側meはself、受信側youはself以外、system/dateは話者なし）。話者を改名する場合はメッセージ内のspeakerとpreviousSpeakerも変更し、追加話者の削除は参照中メッセージの再割当て確認を経て行う。相手→自分／システム→相手へ戻した際には、previousSpeakerに記録した元の相手を優先して復元する。相手側で話者が複数いる場合、話者の表示名・アイコンは参加者設定に従い、既存LINEグループ表示を維持。

TXTインポートでは既存 \`parseMultiline\` → \`parseText\` を使用し、文書へ**コピー**する。元LINE記録にない写真・動画・ファイルの内容は未指定のまま示し、割り当て時だけローカルのFileReaderで紐付ける。画像／動画としてプレビューする形式はPNG/JPEG/GIF/WebP、MP4/WebM。PDF、TXT、ZIP、MP3/OGG/WAVは既知形式のファイルとして、その他の拡張子やMIME種別も`application/octet-stream`の汎用ダウンロードへ変換して扱う（実行可能なHTMLとしてプレビューしない）。入力ファイル1件15MB以下。プロフィールアイコンの選択は安全なラスター画像に限定する。インポートした画像の埋込データやローカルJSON書出しにはユーザーが選んだ実データが入る。公開リポジトリ、LINEサーバ、ChatGPTのメッセージには自動送信しない。

## 永続化と復元

編集中の全状態を、約450msのデバウンスでそのブラウザOriginのIndexedDB \`line-style-editor-cache\` / \`document\` / \`active\` へ自動保存。IndexedDBが使えないとき、1.6MBまでを localStorage に縮退する。いずれも失敗したら画面上にエラーを出す。起動時はIndexedDBの前回内容を復元するが、非同期復元中にユーザーが新規操作した場合には新操作を優先し、古い内容で上書きしない。

ローカルキャッシュは、ブラウザのサイトデータ消去・プライベートブラウズ・別端末等で失われ得る。永続的に渡したいデータは上部の保存で \`.linechat.json\` に書き出す。JSON再読込にはデータ検証と形式制限を通す。保存データに写真やプロフィール画像のbase64データを含む場合、JSONは比較的大きくなる。著作権・個人情報は使用者が管理する。

## 検証

\`tests/\`の旧TXTパーサ・表示回帰84件を壊さない。\`tools/verify_editor_browser.py\` は現物HTML/CSS/JSをChromiumで動かし、空の文書→入力→本文/時刻編集→各要素追加→画像/アイコン設定→プロフィール名→JSON書出し→Y/Xドラッグ→Undo/Redo→IndexedDB再起動復元→JSON取込まで検査。\`tools/verify_wallpaper_browser.py\` は約3000件の架空LINE TXTで背景・表示・画面幅を引き続き検証する。画像と会話内容を含む**ユーザー提供の本家スクリーンショットはリポジトリへコピーしない**。

公開GitHub Pagesへの**実際の反映をマージとは別の受入条件**とし、main push時に正規のPages Actions公開ワークフローを実行、公開URLのHTML/TXTスクリプトまで疎通検証する。実機iPhone Safariでのタッチ・ファイル参照確認はIssue #10が所有する。ブラウザのタッチPointerEvent互換検査は実機Safariの完全な代替ではない。

JSONプロジェクトの読込み上限は120MBで、形式・メッセージ数・埋込データURIを検証し、不正なJSONなら編集中の文書は維持する。外部の実行可能HTML等を埋込ブラウザ画面として表示しない。画像とデータの文字列によってブラウザメモリ使用量は変動する。

## TXT形式の書出し（2026-10-14）

- 既存のLINE TXT書式に準じ、`[LINE] トーク名とのトーク履歴`、`保存日時：YYYY/MM/DD HH:MM`、`# user: 自分の名前`、日付行、`HH:MM<TAB>話者<TAB>本文` をUTF-8 TXTとして保存。全メッセージの自分側の話者には現在の`self`を使用する。元TXTを編集・上書きしない。改行・二重引用符のある本文は引用規則に従って書き出し、現行パーサーで復元する。
- エディターが独自に作った自由文のシステム通知、標準の`HH:MM`以外の時間は、それぞれ`# system-json:`、`# entry-json:`の1行補助レコードに収める。この拡張を理解する本サイトでは型・内容・時刻を再インポートできるが、**純正LINEへのインポート互換を保証するものではない**。
- TXTは文字履歴なので添付された写真・動画・ファイルの**実バイトを含まない**。対応する`[写真]`、`[動画]`、`[ファイル]`の参照だけ保持。プロフィール画像、テーマ、個別編集履歴、メディアバイナリを含む可搬保存はJSONを使う。
- UIの追加機能は原則としてLINE本来の見た目を変えず、タップ選択・ダブルタップ・長押し・設定メニューから呼び出す。指定の「利用者起点」資料の所在はProject Sources検索／共有Drive検索で確認できなかったため、当資料の引用を捏造せず、ユーザーが本チャットで明示した優先順位（本家LINEの表示・操作感を第一、次に相応しい操作・機能の統合）を現在の設計根拠とする。
